# game-ui-restore

一份 spec，四条硬规则，一个检查脚本。没有脚手架，没有模板。

## 文件

```
SPEC.md                怎么还原：坐标系、数据契约、状态、切图决策、取图通道、字体、验收
AGENTS.md              四条硬规则，给 agent 读的短版（先读这个）
scripts/lint_assets.py 机器检查：缺文件 / 切图带底 / 引 SVG / 字体
```

## 怎么用

**给 agent**：把 `AGENTS.md` 的内容直接放进上下文，或者把整个目录给它读。它需要的是判断依据，不是能跑的项目。

**给自己**：开工前读一遍 `SPEC.md` 的 2–5 章（坐标、数据、状态、切图），收工前读 8 章（验收）。

**接进项目**：把 `scripts/lint_assets.py` 复制到项目的 `scripts/` 下，它假设自己在项目根的下一层。

```bash
python3 scripts/lint_assets.py    # 退出码 0 = 通过，1 = 有问题，2 = 不在项目根
```

## 版本

按改动性质打 tag，用 git 锁版本：

```bash
git clone -b v2.0.0 <仓库地址>
```

| 变化 | 版本位 |
|---|---|
| 规则增删、章节结构变（会让人重新判断） | major |
| 加案例、补坑、改措辞 | minor / patch |

看两版之间差了什么：`git diff v1.0.0..v2.0.0 -- SPEC.md`。

## 不含什么

- **切图**：项目资产，几十 MB，进包等于公开。
- **字体**：商业授权（汉仪有圆、方正兰亭圆这类），不能随文档分发。
- **骨架 / 模板 / CLI**：上一版有过，删了。模板会把版式钉死，而版式是每份设计稿自己的事。

## 为什么没有模板

能跨项目复用的只有两样：**决策**（这份文档）和**检查**（那个脚本）。
一个能同时装下网格卡和轮盘的骨架不存在——真有人给你，它一定在偷偷裁设计稿的比例。
