# WORKFLOW.md — 八步流水线

每一步都有输入、产物、过关门槛。**门槛不过，不许往下走**——这次项目的返工，八成都来自 1、2 步没做扎实。

## 总览

| 步 | 动作 | 产物 | 门槛 |
|---|---|---|---|
| 0 | 对齐输入 | 一页交接单 | 拿到画框、比例、背景规则、组件清单 |
| 1 | 读结构 | 图层树 + 变体清单 | 能说清每个部件有几个状态 |
| 2 | 拉资源 | `pieces/` 原图 | 素材带真 alpha，不是截图 |
| 3 | 分层切图 | 按组件拆的 PNG | 四角 alpha=0，无灰底米色底 |
| 4 | 数据建模 | `data/*.js` | 文案、卡片、按钮状态全在数据里 |
| 5 | 搭页面 | `index.html` | 舞台等比缩放，坐标来自测量 |
| 6 | 接交互 | 状态机 | 五种态齐全，迁移不留残影 |
| 7 | 本地核对 | 同尺寸截图 | 与设计稿逐块比对通过 |
| 8 | 打包发布 | 站点 URL | 脚本打包，不手工列文件 |

---

## 0. 对齐输入

要齐这五样，缺一样就先问，别猜：

1. Figma 链接 + 节点 id（要具体到画框，不要给文件首页）
2. 目标比例与像素（如 4680×2160 / 21:9，或 3840×2160 / 16:9）
3. 背景规则（整图多大、居中还 cover、有没有视频）
4. 组件清单（哪些是同款复用、哪些是一页一版）
5. 已有素材（老版本切图、字体、视频）

## 1. 读结构

- `get_metadata` 拿图层树：节点 id、坐标、尺寸、层级。
- `get_design_context` 拿数值：填充、圆角、描边、字号、行高、资源直链。
- 输出一张表：**部件 → 状态变体 → 用哪张**。

**门槛**：能明确回答"选中态是组件自带的，还是要我做？"
如果组件里只有一张占位图（比如 8 个选中变体全是同一个角色），必须停下来问，不许先做再说。

## 2. 拉资源

- 资源走 `get_design_context` 的 `assetPathPrefix`，不用 `get_screenshot`。
- 半透明底板（30% 透明、5% 透明）**不可能**从截图里抠干净，只能走图层或按数值重建。
- 拉完核对：文件大小 > 0、像素尺寸与图层一致、四角透明。

**门槛**：随手抽一张，四角 alpha = 0。

## 3. 分层切图

按这个顺序切，不要混：

1. 不透明整件（卡片、格子、按钮）→ 整块 PNG + 圆角遮罩。
2. 底板 / 纹理 / 行底板 → 单独图层导出，尺寸按图层。
3. 图标 / 星标 / 勾选 → 矢量栅格化成 PNG。
4. 文字 → 不切，用真字体。

**门槛**：`python3 scripts/lint_assets.py` 全绿。

## 4. 数据建模

把这一页会变的东西全抽出来：

```js
APP_DATA.item = {
  title: '全部', total: 100,
  items: [{ img, name, badge, owned, desc, abilities: {}, genes: [] }]
}
```

**门槛**：改文案只改这一个文件；`index.html` 里搜不到一句业务文案。

## 5. 搭页面

- 舞台：固定设计尺寸，`transform: scale(min(w/W, h/H))` 居中。
- 页面区：`[data-p]` 容器，绝对定位铺满，不要用 `display:flex` 去挤舞台。
- 坐标：从第 1 步的图层数值换算，写之前先算换算系数。

**门槛**：随机挑三个元素，页面上量出来的位置和设计稿差 ≤ 2px。

## 6. 接交互

- 状态用 `aria-pressed` / `data-state`，不要用 class 满天飞。
- 选中态整体迁移（先把所有项置 false，再把目标置 true），不要叠加。
- 视频：硬切，不做淡入淡出；循环用双路接力，避免回到第 0 帧黑一下。
- 键盘：Tab 能到，焦点圈可见，Enter / Space 能触发。

**门槛**：连点 5 次不同项，不出现残影、不出现两层同时高亮。

## 7. 本地核对

- 用无头 Chrome 截图，尺寸与设计稿一致。
- 每次用独立 `--user-data-dir`，否则会读到旧缓存，误判"改动没生效"。
- 比对顺序：整体轮廓 → 面板位置 → 文字行 → 图标。

**门槛**：肉眼能对应的位置全部对上；对不上的，能说出差多少像素。

## 8. 打包发布

- 只打包页面真正引用的文件（`deploy.manifest.json`）。
- 包体控制在 60MB 以内，超了先压视频或拆素材。
- 发布用脚本，不手工列文件。

**门槛**：`scripts/build.py` 输出文件数与预期一致；发布后线上能打开。

## 三种常见任务的最短路径

**A. 加一个新页签（同结构，换内容）**
0 → 4 → 5（复制相邻页改尺寸）→ 6 → 8。跳过 2、3（直接复用已有切图）。

**B. 换肤 / 迭代（结构不变，资源更新）**
0 → 1 → 2 → 3 → 7 → 8。只换 `pieces/`，不动数据与版式。

**C. 大改版（版式也变）**
0 → 1 → 2 → 3 → 4 → 5（新写版式，见 `PAGE-CONTRACT.md`）→ 6 → 7 → 8。
其中 0–3 步和 8 步与界面的样子无关，这是可以跨项目复用的部分。
