# PAGE-CONTRACT.md — 页面模块契约

> 回答一个具体担心：**同事要还原的界面和当前结构差很多，这套结构还接得住吗？**
> 先给结论：**这套东西抽象的是"管线"，不是"版式"。版式差异再大也不影响复用，因为版式从来没被抽象过。**

## 1. 复用的是哪一层

```
复用（不随界面变）
├── 舞台：等比缩放到窗口、居中、不吃滚动条
├── 页签：一级分类、点线、选中态、悬停、移动端按压
├── 背景：场景图 / 视频层、切换策略、兜底层
├── 数据：一份 data/*.js，页面只读不算
├── 资源纪律：切图规则、命名、字体策略
├── 校验：lint + 同尺寸截图比对
└── 发布：manifest + build + deploy

不复用（每个界面自己写）
└── 页面内部版式：几列、几行、面板放左还是放右、字号层级
```

换句话说：**换的是"屋里怎么摆"，不换"房子在哪、水电怎么接"。**

## 2. 三种参考版式是起点，不是限制

项目里现成的三种，用来抄结构、抄层级、抄状态写法：

| 参考 | 用在哪 | 特征 |
|---|---|---|
| 卡片网格页 | 服装 / 皮肤列表 | 左分类 + 3 列卡片 + 右侧信息 |
| 列表详情页 | 武器 / 技能 | 左列表（横向条）+ 右侧属性 |
| 网格详情页 | 道具 / 背包 | 多列格子 + 右侧长面板 |

新界面和这三种都不像，就**新写一个版式**，只保留契约要求的那几项（见第 3 节）。不需要为了"复用"去改造型。

## 3. 页面模块必须满足的契约

新增一个页面，只需要提供这六样，别的一概不动：

1. **一个容器**：`<div class="page3" data-p="页面key">`，绝对定位铺满页面区。
2. **一条页签数据**：`tabs: [{ label, page }]` 里 `page` 指向这个 key。
3. **一个显隐规则**：`#stage[data-page="key"] .page3[data-p="key"]` 显示，其他隐藏。
4. **一个渲染函数**：读 `APP_DATA.<你的模块>`，生成 DOM；不要在这里写死文案。
5. **一个选择模型**：`aria-pressed` 标记当前项，同一时刻只有一个为 true。
6. **一个资源前缀**：本页切图放 `pieces/<页面key>/`，不要和别的页混。

满足这六条，页面就能和现有页面共存：页签能切、返回按钮在、资源栏在、发布脚本能打包。

## 4. 差异性怎么处理

| 差异 | 处理 |
|---|---|
| 卡片尺寸、列数、行距不同 | 改这一页的 CSS 变量，不动别的页 |
| 面板在左不在右 | 版式自己写，数据同理 |
| 没有"选中"概念（纯展示页） | 第 5 条契约可以不实现，但要在注释里写明 |
| 有滚动 / 分页 | 容器内滚动，**不要**让整个舞台滚动 |
| 全屏演出（旋转轮盘、3D 展台） | 只复用 0–3 步和发布链路，版式与交互自己写；分层规则照样要守 |
| 一页多状态（列表/详情/编辑） | 用 `data-state` 切换，不要复制三份 DOM |

## 5. 什么时候该"重写版式"，什么时候该"套模板"

- 新页面 **80% 以上的部件在 Figma 里是图**（卡片、格子、面板）→ 套模板，只换尺寸和列数。
- 新页面 **大量是纯文本、表单、长列表** → 版式重写，切图只用于底板和图标。
- 新页面是**全屏演出 / 动效为主** → 只借舞台、页签、发布链路。

## 6. 反模式

- 为了让新页面"塞进"现有模板，把 400×560 的卡硬缩成 200×280 —— 会糊，也会被一眼看出来是凑的。
- 为了复用而改现有页面的结构 —— 会连带回归别的页。
- 把三个页面的 CSS 写成一个巨大的选择器 —— 改一页会误伤两页。
